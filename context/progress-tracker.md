## Architecture decisions (append-only log)

- 2026-05-04 — **`react-player` mock is double-targeted (spec 03 deviation)**: spec 03 says "mock `react-player`", but `TrailerPlayer` imports the YouTube subpath `react-player/youtube`. `vi.mock` is keyed on the imported specifier, so a bare `'react-player'` mock would silently no-op. We mock both specifiers with the same factory — defensive against any later component reaching for either path. Verified via probe test: `screen.getByTestId('player')` resolves with `data-playing="true"` / `data-muted="true"` attributes.
- 2026-05-04 — **`vitest.config.js` adds `plugins: [react()]` and `coverage.provider: 'v8'` (spec 03 deviation)**: spec 03's literal config omits both. Without `react()`, Vitest's transformer cannot handle JSX in `.jsx` test files; the sample test would fail to parse. Without `provider: 'v8'`, vitest defaults the coverage provider away from the installed `@vitest/coverage-v8`. Both are non-negotiable for the harness to actually function.
- 2026-05-04 — **`test-setup.js` keeps `.js` extension and uses `React.createElement` (spec 03 deviation)**: spec 03 named the file `src/test-setup.js`. `@vitejs/plugin-react` only transforms JSX in files Vite considers JSX (`.jsx`/`.tsx`); a single `.js` containing JSX would risk a parse error. We honored the spec's filename and emit the react-player stub via `React.createElement('div', { ... })` instead of JSX. One line, no ergonomic loss.
- 2026-05-04 — **`tsconfig.json` `types` array added (spec 03 deviation)**: with `checkJs: true`, the bare `import '@testing-library/jest-dom/vitest'` runtime registration is not enough to extend `expect`'s TypeScript surface; calls like `expect(x).toBeInTheDocument()` would emit TS2339. Added `"types": ["vitest/globals", "@testing-library/jest-dom"]`. `vitest/globals` is also defensive for the `globals: true` flag in `vitest.config.js`. Caveat: setting `types` narrows ambient type acquisition; later specs that need additional ambient packages must append, not replace.
- 2026-05-04 — **`src/test-globals.d.ts` ambient declarations (spec 03 deviation)**: `globalThis.__triggerIntersection` and `__setPrefersReducedMotion` are assigned in `test-setup.js` but consumed (in future specs) from test files. Without an ambient declaration, every consumer would emit TS2339 on `globalThis`. One six-line `.d.ts` augments `globalThis` once. The `reel/require-ts-check` rule's glob is `.{js,jsx}`, so `.d.ts` is unaffected.
- 2026-05-04 — **ESLint test-files override disables `import/no-restricted-paths` for `src/shared/test/**`(spec 03 deviation)**:`redux-wrapper.jsx`lives under`shared/test/`but legitimately imports`@/entities/user/user-slice`to compose a real reducer for tests; the FSD zone rule (shared cannot import from entities) would block it. Narrow override on a test-only glob is the smallest honest exception. The override also disables`react-refresh/only-export-components` on the same glob (test wrappers export both factories and components).
- 2026-05-04 — **`redux-wrapper.jsx` uses `combineReducers` (spec 03 deviation, type-driven)**: passing `{ user: userReducer }` directly into `configureStore` while also typing `preloadedState` as `Partial<...>` triggered TS overload-resolution to pick the "single Reducer" form, breaking `reducer: { user: ... }`. Wrapping with `combineReducers({ user: userReducer })` collapses to one Reducer up front, then `preloadedState: Partial<ReturnType<typeof rootReducer>>` resolves cleanly. Production `src/app/store.js` was untouched.
- 2026-05-04 — **tsconfig drops `baseUrl` (spec 02 deviation)**: TypeScript 6.0 deprecated `baseUrl` and removes it in 7.0. Spec 02's literal JSON included `"baseUrl": "."`; we kept the same effect by writing `"paths": { "@/*": ["./src/*"] }` (leading `./`) without `baseUrl`. Identical resolution behaviour, future-proof under TS 7.
- 2026-05-04 — **JSDoc rule scoping (spec 02 deviation)**: spec 02's literal text says `jsdoc/require-param`/`jsdoc/require-returns` should run "on exported functions only (skip arrow callbacks, hooks, components — TypeScript-checking handles those)". The plugin's `contexts` API can't cleanly express "exported plain functions but not exported arrow utilities or hooks", and `@ts-check` + `checkJs` already enforces param types via TS7006. We turned `require-param` and `require-returns` off and kept the validity rules (`check-param-names`, `check-tag-names`, `check-types`) — when JSDoc IS written, it must be syntactically valid; when it's not, TS catches the gap. Same coverage, cleaner config, no false positives on components.
- 2026-05-04 — **`@ts-check` and `@ts-ignore` enforced via inline custom rules**: spec 02 said "ESLint custom rule pattern" without naming a package. We defined two tiny inline rules in `eslint.config.js` (`reel/require-ts-check`, `reel/no-ts-ignore`) instead of pulling another plugin. Keeps the dep list lean; rules are <40 LOC each, well-supported in flat config. `@ts-expect-error` is permitted (with reason) — see `src/shared/ui/trailer-player.jsx` for the lone v1 exemption.
- 2026-05-04 — **`eslint-import-resolver-typescript` added (spec 02 deviation)**: spec 02 didn't list a path-alias resolver in its dep list, but `import/no-restricted-paths` only fires on resolved paths and the codebase imports exclusively via `@/` aliases. Without the resolver the rule silently no-ops, breaking spec 02 success criterion #5. The resolver reads `tsconfig.json` paths automatically — no additional config beyond `settings['import/resolver']`.
- 2026-05-04 — **`eslint-plugin-react` added (spec 02 deviation)**: enabling `js.configs.recommended.rules` introduced `no-unused-vars`, which (without JSX awareness) flagged every JSX-imported component. The standard fix is `react/jsx-uses-vars` from `eslint-plugin-react`. We enabled only `jsx-uses-vars`, with `react-in-jsx-scope` and `jsx-uses-react` off (React 19's new JSX runtime makes them unnecessary).
- 2026-05-04 — **`Movie` typedef in `src/shared/api/tmdb.js`**: defined as `Record<string, any>` for v1. _Reason: TMDB responses have many optional fields (videos, credits, similar, genres, runtime), and a strict shape would force premature `@ts-expect-error` exemptions across consumers. The looser typedef preserves @ts-check + checkJs as the param-typing backbone without turning every catalogue tile into a type puzzle. A later spec dedicated to TMDB types can tighten it._

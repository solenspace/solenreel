## Architecture decisions (append-only log)

- 2026-05-05 — **`Movie.posterPath` stores raw TMDB path; size chosen at render via `posterUrl(path, size)` (spec 09)**: the entity holds the raw `/abc.jpg` path TMDB returns, not a pre-prefixed URL. Consumers compute the final URL with `posterUrl(path, size = 'w342')` (and `backdropUrl` / `logoUrl` / `profileUrl` siblings) re-exported from `@/entities/movie/queries.js`. Reasoning: (1) different surfaces want different sizes — tile posters at `w342`, modal hero at `original`, cast strip at `w185` — locking the size at fetch time would force re-fetches for surface variation; (2) image base URLs are TMDB plumbing, not domain data — putting them in the entity bleeds infrastructure into the data layer. Each `*Url` helper returns `null` on null/undefined input (tighter than the previous `undefined`) so consumers branch with `if (!url) return null` instead of conditional rendering on the path. The previous `img.{poster,backdrop,logo,profile}` object helper was removed entirely; named exports are easier to grep and tree-shake. Documented sizes per surface live in JSDoc on each helper.
- 2026-05-05 — **`useSearchMulti` owns the debounce internally; consumers type freely (spec 09)**: `useSearchMulti(query)` runs `const debounced = useDebounce(query, 400)` inside the hook and passes `debounced` to both the query key and the `enabled: debounced.length >= 2` guard. Consumers pass the raw input value directly. The previous pattern in `src/app/pages/search.jsx` was a manual `useDebounce(query, 400)` + `useSearch(debounced)` two-step that leaked the timing concern into every consumer. Pulling debounce into the hook means: (1) consumers never see stale data because they pass the live value, (2) the test can `vi.useFakeTimers()` + `vi.advanceTimersByTime(400)` to verify no per-keystroke fetch fires (verified in `queries.test.jsx`), (3) debouncing is a single concern owned by the hook, not duplicated across pages. The standalone `useDebounce` in `src/shared/lib/use-debounce.js` is kept (other features may need it) but `search.jsx` no longer imports it.
- 2026-05-05 — **Re-export `*Url` + `genreIdsToNames` + `GENRES` from `queries.js`; consumers never reach for `@/shared/api/tmdb` directly (spec 09)**: success criterion 3 wants `grep "from '@/shared/api/tmdb'" src/` to land only on `queries.js` (and its tests). Consumers import `posterUrl` etc. from `@/entities/movie/queries`, not from the shared client. The shared client stays the single concentration point for axios + URL composition + genre map data; the entity layer is the public consumer surface. Verified by grep: `from '@/shared/api/tmdb'` appears only in `src/entities/movie/queries.js` (split import block lands on two lines).

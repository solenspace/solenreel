## Architecture decisions (append-only log)

- 2026-05-04 — **tsconfig drops `baseUrl` (spec 02 deviation)**: TypeScript 6.0 deprecated `baseUrl` and removes it in 7.0. Spec 02's literal JSON included `"baseUrl": "."`; we kept the same effect by writing `"paths": { "@/*": ["./src/*"] }` (leading `./`) without `baseUrl`. Identical resolution behaviour, future-proof under TS 7.
- 2026-05-04 — **JSDoc rule scoping (spec 02 deviation)**: spec 02's literal text says `jsdoc/require-param`/`jsdoc/require-returns` should run "on exported functions only (skip arrow callbacks, hooks, components — TypeScript-checking handles those)". The plugin's `contexts` API can't cleanly express "exported plain functions but not exported arrow utilities or hooks", and `@ts-check` + `checkJs` already enforces param types via TS7006. We turned `require-param` and `require-returns` off and kept the validity rules (`check-param-names`, `check-tag-names`, `check-types`) — when JSDoc IS written, it must be syntactically valid; when it's not, TS catches the gap. Same coverage, cleaner config, no false positives on components.
- 2026-05-04 — **`@ts-check` and `@ts-ignore` enforced via inline custom rules**: spec 02 said "ESLint custom rule pattern" without naming a package. We defined two tiny inline rules in `eslint.config.js` (`reel/require-ts-check`, `reel/no-ts-ignore`) instead of pulling another plugin. Keeps the dep list lean; rules are <40 LOC each, well-supported in flat config. `@ts-expect-error` is permitted (with reason) — see `src/shared/ui/trailer-player.jsx` for the lone v1 exemption.
- 2026-05-04 — **`eslint-import-resolver-typescript` added (spec 02 deviation)**: spec 02 didn't list a path-alias resolver in its dep list, but `import/no-restricted-paths` only fires on resolved paths and the codebase imports exclusively via `@/` aliases. Without the resolver the rule silently no-ops, breaking spec 02 success criterion #5. The resolver reads `tsconfig.json` paths automatically — no additional config beyond `settings['import/resolver']`.
- 2026-05-04 — **`eslint-plugin-react` added (spec 02 deviation)**: enabling `js.configs.recommended.rules` introduced `no-unused-vars`, which (without JSX awareness) flagged every JSX-imported component. The standard fix is `react/jsx-uses-vars` from `eslint-plugin-react`. We enabled only `jsx-uses-vars`, with `react-in-jsx-scope` and `jsx-uses-react` off (React 19's new JSX runtime makes them unnecessary).
- 2026-05-04 — **`Movie` typedef in `src/shared/api/tmdb.js`**: defined as `Record<string, any>` for v1. _Reason: TMDB responses have many optional fields (videos, credits, similar, genres, runtime), and a strict shape would force premature `@ts-expect-error` exemptions across consumers. The looser typedef preserves @ts-check + checkJs as the param-typing backbone without turning every catalogue tile into a type puzzle. A later spec dedicated to TMDB types can tighten it._
- 2026-05-04 — **TrailerPlayer placement (spec 01 deviation)**: placed at `src/shared/ui/trailer-player.jsx` instead of the spec's literal `src/features/trailer/trailer-player.jsx`. _Reason: Banner (widget) and MovieModal (feature) both consume it; placing it in `features/` would create a layer-direction violation (widgets cannot import from features) and fail spec 01 success criterion #6. The component is a stateless prop-driven `react-player` wrapper with zero domain logic — fits `shared/ui` exactly. fsd-architect verified zero violations on the post-restructure tree._
- 2026-05-04 — **firebase.js placement (spec 01 implicit decision)**: `src/firebase.js` moved to `src/shared/api/firebase.js` (next to `tmdb.js`). _Reason: spec 01's enumerated layer mapping covers every other imported file; leaving firebase at `src/` root would be the only non-Vite-entry exception. Spec 05 will replace it with `src/shared/api/supabase.js` — same neighborhood, cleaner diff._
